\begin{abstract}
Self-consistency selects among $N$ sampled LLM answers by majority vote,
but is undefined when candidates do not repeat verbatim -- the common
case for open-ended queries. We formulate best-of-$N$ selection instead
as an integer program over an LLM-judged pairwise comparison matrix, a
deterministic self-consistency term, confidence, and cost, solved exactly
with CP-SAT. Given fixed inputs the solve is exactly reproducible; we
find empirically that the inputs are not always stable, and report both
a concrete provider-side seed-non-determinism failure and the fix that
closes it. Across two evaluation tracks -- open-ended queries with no
ground truth, and GSM8K with a checkable answer -- the method diverges
from simpler baselines exactly when candidates diverge and ties with them
when candidates converge, as predicted by the same mechanism from both
directions. Two ablations give opposite results: bidirectional
(permutation-self-consistent) judging changes the selected winner in 2 of
3 cases tested; the deterministic self-consistency term has changed none
of 3, for a structural reason we identify. We report this as a
preliminary, small-scale, honestly-limited study, including a
methodological error we found and fixed during the work.
\end{abstract}

\section{Introduction}

Self-consistency \citep{wang2023selfconsistency} picks among $N$ sampled
LLM answers by majority vote over final answers. This is well-defined
only when candidates cluster; on open-ended queries, where independent
samples rarely repeat verbatim, it degenerates to an arbitrary tie-break.
We measure this directly: across 3 open-ended queries ($N=5$ each), 0 of
15 candidates matched any other candidate for the same query exactly.

We treat selection, not generation, as the object to make deterministic.
An LLM judge produces a pairwise preference matrix over already-sampled
candidates; an integer program combines it with a deterministic
self-consistency signal, a confidence estimate, and a cost penalty to
pick exactly one winner. The solve is exactly reproducible given fixed
inputs -- this is proved by construction (CP-SAT, single search worker).
What is not automatically reproducible is whether the judge and scoring
calls themselves are stable across runs, since they are LLM calls; we
measure this rather than assume it, and report a concrete failure we
found and fixed.

\textbf{Contributions:} (1) an IP formulation combining LLM-judged
pairwise quality with a deterministic self-consistency term as one
additive signal rather than a competing method; (2) a live-tested finding
that a seed-supporting provider returned non-symmetric pairwise scores
for byte-identical text -- mathematically impossible if seeding were
honored -- and a fix that closes this case; (3) a two-track evaluation
(no ground truth / ground truth) motivated by the finding that judge
calibration does not predict selection accuracy \citep{landesberg2026bestofn};
(4) two ablations with opposite outcomes, reported honestly including a
data-hygiene bug we caught mid-study.

\section{Method}

Given a query, sample $N$ candidates (only non-deterministic stage);
score each for confidence $\in[0,1]$ and cost (token count); build a
pairwise matrix $W[i,j]$ by judging each unordered pair in both text
orders and averaging \citep{tang2024permutation}, which corrects the
positional bias documented by \citet{zheng2023judging} -- the reverse
entry is derived as $1-W[i,j]$, not re-judged; pairs with byte-identical
text skip the judge entirely and receive the forced $W[i,j]=0.5$ (Section
\ref{sec:finding} motivates this). Compute
$\text{consistency}_i = |\{j:\text{text}_j=\text{text}_i\}|/N$ by string
comparison, zero API cost. Solve:
\begin{equation}
\max \sum_i x_i \left( w_1 q_i + w_2 c_i + w_4 s_i - w_3 k_i \right)
\quad \text{s.t.} \quad \sum_i x_i = 1,\ x_i \in \{0,1\}
\end{equation}
where $q_i$ (quality) is the Copeland-style mean pairwise win rate --
a Kemeny-Young approximation \citep{llmjudgethemselves2025} -- $c_i$
confidence, $s_i$ self-consistency, $k_i$ cost. Default weights
$(1.0, 0.2, 0.3, 0.01)$, not tuned.

\section{Experiments}

Live results use OpenRouter (\texttt{nvidia/nemotron-3-ultra-550b-a55b:free})
as generator, scorer, and judge -- a single free-tier model, chosen for
availability; two other configured providers (OpenAI, Gemini) were
unavailable throughout (no credits; daily quota exhausted respectively),
preventing a heterogeneous-judge run and leaving open whether this design
reduces the correlated-judge-error problem documented by
\citet{correlatederrors2026} or merely adds cost.

\textbf{Baselines:} self-consistency alone (majority vote, no judge, no
IP); greedy single-sample (no ensemble).

\textbf{Track A} (open-ended, no ground truth): 3 queries, $N=5$.
\textbf{Track B} (GSM8K, ground truth): a growing sample of the public
GSM8K test set \citep{wang2023selfconsistency}, $N=3$; final answer
extracted by taking the last number in the response.

\section{Results}

\textbf{Track A.} OR-Select disagreed with both baselines on 3 of 3
queries. Self-consistency had no true majority in any of the 3 (0/15
candidates matched), resorting to an arbitrary tie-break that happened to
coincide with the greedy pick every time. Margins were not uniform: two
queries showed a clear quality gap (0.09, 0.45 in internal score units);
the third was a near-tie (0.003) between paraphrases of one answer --
reported as such rather than averaged into a uniform "wins" claim.

\textbf{Track B.} All 40 attempted problems graded (after recovering from
a temporary provider outage affecting problems 24-40, a session-cap-
shaped failure excluded from accuracy during the outage rather than
counted as wrong -- see the accompanying repository). All three methods
tie at 100\% accuracy on all 40, because every candidate independently
converged on the identical correct answer every time -- zero
disagreement across the entire run. This is the predicted complement to
Track A, not a null result: baselines and OR-Select should tie when
candidates cluster and diverge when they do not, both halves now
independently observed. Per \citet{kim2025correlated,ding2026agree},
this is expected: stronger models produce more correlated, lower-
diversity samples, and GSM8K is saturated for the model used here --
MATH Level 5, AIME, or GPQA Diamond are the literature-motivated next
benchmark.

\textbf{Track C (MATH Level 5).} We attempted this next step
(\citet{lightman2023letsverify}'s MATH-500, Level-5 subset, 134
problems). Severe free-tier rate-limit saturation (worker limits reached
at up to 6$\times$ stated capacity) stalled the run after only 4
problems attempted (2 valid, 2 recorded as explicit timeout failures); a
fixed time budget stopped it there. The 2 valid problems again tied,
0/2 disagreement -- too small to conclude anything about saturation at
this difficulty; it shows the attempt was blocked by infrastructure, not
that the benchmark choice was wrong.

\textbf{Ablations.} Self-consistency term: 0 of 3 winners changed when
$w_4{=}0$ (fully offline, exact inversion of the known scoring formula --
see repository for method). Not close: consistency spread was exactly
0.000 in all 3, because every observed candidate set was fully diverged,
and a constant cannot change an arg max. \emph{An earlier pass wrongly
included two pre-fix files and reported "0 of 5"; caught and corrected
mid-study.} Permutation
self-consistency: forward-only (no backward averaging) judging changed
the winner in 2 of 3 comparisons against the same Track A candidates
(rent-vs-buy, Hamlet changed; traffic congestion did not) -- the
opposite pattern from the term ablation, though not a universal one.
Bidirectional judging is load-bearing most of the time; the
self-consistency term, as weighted, has not yet mattered on any valid
data collected.

\section{A Concrete Non-Determinism Finding}
\label{sec:finding}

Three live candidates with byte-identical text should force every
pairwise weight among them to exactly $0.5$: forward and backward calls
are the literal same prompt, so $(v+(1-v))/2=0.5$ regardless of the
model's output. Observed quality scores were $0.375$, $0.50$, $0.625$ --
direct evidence the provider's \texttt{seed} parameter is not reliably
honored, not a theoretical caveat. The exact-match short-circuit in
Section 2 closes this specific case; it does not address whether two
\emph{different} texts receive stable judge scores across runs, which
remains open.

\section{Limitations}

Scale: $N{=}3$--$5$ and single-digit-to-40-item query counts, dictated by
free-tier rate limits (queue depths up to 3517/32, worker limits up to
196/32), not by design -- this is a preliminary report. Single judge
model throughout, with the correlated-error risk
\citep{correlatederrors2026} untested. No test yet of the scenario that
most directly probes the hypothesis: candidates disagree, the majority
is wrong, and OR-Select's judge selects a correct minority answer.
Track B (0/40) is explained by saturation
\citep{kim2025correlated,ding2026agree}; Track C targeted this directly
on an unsaturated benchmark but was cut short by rate limits at $N{=}2$
(Section 4) -- closing this gap now needs a paid tier or fewer API calls
per problem, not just a harder dataset.

\section{Conclusion}

Selection among $N$ LLM samples is exactly reproducible given fixed
judge/score inputs; those inputs are not automatically stable, and we
measure rather than assume this, finding and closing one concrete
failure. The method diverges from naive baselines exactly when
candidates diverge and ties with them otherwise, confirmed from both
directions. One design component (permutation self-consistency)
demonstrably matters; another (the self-consistency term) has not yet,
for a structural reason identified by ablation, not assumption. We
report a data-hygiene error caught mid-study as part of the record, not
edited out.
